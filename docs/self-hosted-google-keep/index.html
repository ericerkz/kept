Self-hosted Google Keep: run Kept on your own server

Kept is an open-source notes app with the colourful, quick-capture feel of Google Keep, and a server you can run yourself. This guide takes you from an empty folder to a working server with HTTPS, mobile sync and backups.

What a self-hosted server gives you

You don't need a server to use Kept: the native apps can keep notes only on your phone (see offline notes). A server adds everything that involves more than one device or person:

Sync everywhere

Your iPhone, Android phone, tablet and any browser see the same notes. Apps keep working offline and catch up when they reconnect.

A web app

Use Kept from any computer, or install it as a home-screen app (PWA) with push reminders.

Sharing

Share notes and binders with other people on your server and edit together in real time.

Your data, your disk

Everything lives in one ./data folder: an SQLite database plus your images and attachments.

Kept is licensed under the AGPL-3.0 and free to self-host, with no per-user limits. If you'd rather not maintain a server, Kept Cloud runs the same server software for you.

What you need

  • A machine that runs Docker with Compose. A home server, NAS, mini PC or small VPS all work. The published image is built for linux/amd64 and linux/arm64, so 64-bit Raspberry Pi and ARM servers are covered.
  • A domain name with HTTPS, if you want to reach Kept from outside your home network or use web push notifications. On a LAN or VPN (Tailscale, WireGuard) you can start without one.
  • Unraid users can skip Compose and install Kept from Community Applications.

Install with Docker Compose

  1. Create a folder and a docker-compose.yml

    This is the smallest working setup. The repository's own docker-compose.yml has every optional setting commented out, if you'd rather start from that.

    services:
  kept:
    image: ghcr.io/ericerkz/kept:latest
    container_name: kept-app
    ports:
      - "6767:6767"
    environment:
      - PUID=1000
      - PGID=1000
    volumes:
      - ./data:/app/data
    restart: unless-stopped

    PUID and PGID make the files in ./data owned by your user on the host (run id to check your numbers), so you can back them up without sudo.

  2. Start it 
    docker compose up -d

    Prefer cloning the repository? git clone https://github.com/ericerkz/kept.git && cd kept && docker compose up -d does the same thing with the full example file.

  3. Open it

    Go to http://localhost:6767, or http://<server-ip>:6767 from another computer on your network.

First run: the admin account

The first visit opens a setup screen. Create the admin account there; it's the account that manages users, backups and server settings. The setup screen also has two shortcuts:

  • Import from Google Keep: tick it to go straight to the importer after setup. See migrating from Google Keep.
  • Restore from backup: upload a full server backup instead of creating a new account. It only works when the server is started with KEPT_ALLOW_RESTORE=1. Use it when moving an existing Kept server to new hardware.

Put it behind HTTPS

For access from outside your network, point a domain at your server and proxy it to port 6767 with Nginx, Apache, Caddy, Traefik or a tunnel. Two things matter:

  • Proxy WebSockets on /api/realtime. Live collaboration and online status use it. Everything else still works without it, but shared notes only update when you refresh.
  • Allow large uploads if you plan to import a big Google Takeout ZIP or restore a backup through the proxy. Kept accepts Takeout files up to 5 GB by default, but a proxy or CDN may reject them sooner.

A minimal Caddy setup, which fetches certificates automatically:

kept.example.com {
    reverse_proxy 127.0.0.1:6767
}

Caddy passes WebSockets through on its own. For complete Nginx and Apache examples, see the reverse proxy section on the main page.

Behind Cloudflare Access, Pangolin or another login gateway? The browser goes through the gateway's login as normal. The iOS and Android apps can send custom headers (such as a Cloudflare Access service token) to get through, and the iOS app also supports client certificates. Live updates over WebSockets can't carry those headers, so behind header-only gateways shared notes update when you switch back to the app.

Connect the iOS and Android apps

  1. Install the app

    Get Kept Notes from the App Store or Google Play.

  2. Choose your own server

    On the welcome screen, choose Your own server and enter its address, for example https://kept.example.com. The app remembers it and reconnects automatically.

  3. Sign in

    Use the account you created on the server. Notes sync both ways, and you can keep editing without a connection.

Already using the app in device-only mode? Settings → Notes on this device → Move my notes to a server transfers your whole library, including images and attachments.

Add family or teammates

Everyone on your server gets their own private notes. As admin, open Users/Admin settings to:

  • let people register themselves, optionally requiring your approval first;
  • invite people by email, if you configure SMTP;
  • let people sign in with an OpenID Connect provider such as Authentik, Pocket ID or Google (see the OIDC guide).

Once people share a server, they can share individual notes or whole binders with each other.

Backups and restore

Kept has two kinds of server backup, and they protect different things:

BackupWhat's in itWhen to use it
Scheduled backupsThe database only (notes, accounts, settings). Daily, weekly or monthly, with retention rules.Frequent safety net against mistakes.
Full server backupOne ZIP with the database, all images and attachments, and the web push keys.Moving servers, or recovering from a lost disk.

To restore, start a fresh server with KEPT_ALLOW_RESTORE=1, upload the ZIP on the setup screen before creating any account, then remove the setting and restart. Encrypted (locked) notes restore too, and still open with their passcode. Copying the whole ./data folder while the container is stopped also works.

A full backup contains every user's notes. Store it somewhere private.

Updating

docker compose pull
docker compose up -d

Your ./data folder isn't touched by updates. Release notes are on GitHub. Update the mobile apps too, especially before using new features such as encrypted notes.

Common questions

Does Kept need Postgres or Redis?

No. Kept stores everything in SQLite inside ./data, so the container is the only thing to run.

Can I use it only on my home network?

Yes. Kept works over plain HTTP on a LAN or VPN. You'll need HTTPS for web push notifications in the browser and for installing the PWA on iOS.

Is my data end-to-end encrypted on the server?

Not by default: the server can read normal notes, which is what lets search, sharing and the web app work. For sensitive notes, lock them with a passcode. Their text, checklists, images and attachments are then encrypted on your device with AES-256-GCM before they're saved, and the server only stores ciphertext. Titles and basic metadata stay visible.

Can I connect AI assistants or other tools?

Optionally. Kept has an OAuth 2.1 server and an MCP server, both off until each user turns them on. See the MCP guide.
